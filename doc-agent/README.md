# 智能单据自动录入系统（doc-agent）

面向制造业「纸质单据手工录入」场景的自研系统：单据拍照拖进网页 → 视觉大模型输出结构化数据（单号/供应商/明细/合计）→ 多层校验 → 入库导出。

**在线演示**：https://doc-ocr-probe.app.workbuddy.host

## 核心设计：七层流水线

```text
去红章 → 视觉模型直读抽取 → 规则校验 → 勾稽校验 → 出处校验 → 疑点看图复核 → 人工确认入库
```

每一层的存在都在回答一个问题：**凭什么相信模型这次没有抽错？**

- **规则校验**：格式、必填、取值范围；
- **勾稽校验**：数学恒等式（明细金额之和 = 合计、数量×单价=金额）——模型编不出来；
- **出处校验**：每个字段必须能在原图上找到来源坐标，防止"看起来对但图里没有"的幻觉；
- **看图复核**：前几层判存疑的记录，服务端强制再看一次图，不和模型的第一遍结论商量；
- **人工确认入库**：最后一道闸门永远是人。

## 评测

自建两套各 20 张评测集，脚本直打线上接口、可重跑：

- 全字段准确率 100%、误放行 0；
- ~2100 token/张，p50 延迟 665ms；
- 链路选型（纯 OCR / 纯直读 / 直读+兜底）全部用成本与延迟实测说话；兜底链路做了盈亏平衡测算（兜底触发率超过 34% 才划算）。

一个评测方法论教训：形近字符（如 SimSun 字体里 `O` ≡ `0`）在字面严格口径下永远"错"，**样本层面不可判的量测出来的不是能力是先验**——主表用可判口径，另列字面严格率，差值就是模型的代偿量。

## 防御性设计

- **提示词注入实测 23 个主流模型**：2 个被图片内嵌指令改写业务字段 ⇒ 确立"模型输出只当待验证输入、结论由服务端重算"；
- 强流程任务不引入 Agent 自主性——固定流水线 + 人工闸门，知道什么时候不用 Agent 是做 Agent 系统的第一课。

## 目录结构

```text
doc-agent/
├── app.py            # 服务端入口（FastAPI，多页应用 + 接口）

├── tools/            # 文档渲染等辅助工具
└── demo/             # 架构演进说明与生成脚本
```
