# 货物台账 AI 助手（cargo-ledger）

为一个做批发生意的真实客户交付的运营台账：把一张腾讯文档多维表格变成"会自己说话的台账"。已完整交付上线（在线演示见文末）。

## 业务闭环

```text
下单人填单报单 → 运营在台账网站审核 → 审核通过入库
                → 打开网站自动批量追踪物流
                → 行情监控：跌破成本自动提醒
```

- 老板一句话「跑下物流」替代每日人工查件：AI 自动批量拉取快递轨迹、生成「今天/明天到货」日报、在途与待发货分开展示，手机打开即看；
- 行情报价图拍照上传，视觉模型逐行识别更新行情价，跌破成本 / 异常波动 / 数据过期自动体检。

## 设计亮点

### 写入门控：AI 读自由，写受限

任何改表操作走两阶段确认——AI 先生成差异预览和一次性确认票据（5 分钟有效、绑内容、用后作废），运营确认后才落库。真实生意的数据，一次误改都承受不起。

### 统计证据闸门

最有价值的教训：上线联调发现统计口径错误——37 条只下单未发货的记录被算成「在途 38 单」，实际一个包裹都没在路上。修复后立下规矩：**「在途」= 有快递单号或有物流轨迹，且未签收未退回；没有原始证据的数字不许进统计**。AI 提效的瓶颈往往不在模型，而在业务口径有没有说清。

### 真实世界的脏数据逐个排掉

- 空单元格被序列化成字符串 `"None"`，把空行算成在途；
- 复选框字段值藏在另一存储列（`bool_value`），按文本读永远是"未勾"；
- 文档 ID 三套体系互不认（短 ID / 链接 ID / 内部 ID），混用报错且 msg 为空。

每个坑都做成通用处理规则沉淀复用，不二次踩。

### 物流通道纪律

- provider 绝不默认 mock：mock 是按单号哈希生成的假轨迹，一旦进台账就是伪造业务数据；
- 免费端点失败自动降级付费端点；`Success=true 但 Traces 为空` ≠ 没物流，可能是通道不覆盖，继续试下一端点；
- 内置探针体检脚本：发格式合法但不存在的单号自检凭证与套餐状态，不耗真实查询次数。

## 目录结构

```text
cargo-ledger/
├── app.py           # 服务端入口（FastAPI + 静态页）
├── auth_gate.py     # 口令登录门（fail closed：未配置则整站锁死）
├── cloud.py         # 云数据库通道
├── carriers.py      # 快递鸟物流查询（签名 / 端点降级 / 手机后四位校验）
├── parse_order.py   # 订单解析
├── quote_parse.py   # 行情报价图识别
├── tdoc_oauth.py    # 腾讯文档 OAuth（client_secret 走环境变量）
├── web/             # 前端页面
├── tools/           # 运维工具（凭证体检 / 样例生成 / 利润模型）
└── config.example.json  # 配置模板：复制为 config.json 并填入自己的凭据
```

## 快速开始

```bash
pip install -r requirements.txt
cp config.example.json config.json
# 编辑 config.json：
#   1. 填入你自己的腾讯文档 file_id / sheet_id（多维表格）
#   2. 注册腾讯文档开放平台，填 client_id，client_secret 用环境变量 TDOC_CLIENT_SECRET 注入
#   3. 申请快递鸟账号，填 kdniao_ebusiness_id / kdniao_app_key
#   4. 生成登录口令哈希：python -m auth_gate set-password
python app.py
```

> ⚠️ 本仓库不含任何真实凭据与业务数据；`config.json` 已被 `.gitignore` 排除，切勿提交。
