# AI Agent 实战合集

三个跑在真实场景里的 AI Agent 项目，覆盖「感知 → 抽取 → 校验 → 入库 → 追踪 → 分析」完整链路：

| 项目 | 一句话定位 | 技术栈 | 状态 |
| --- | --- | --- | --- |
| [doc-agent/](doc-agent/) | **智能单据自动录入系统**：单据拍照 → 结构化抽取 → 三层校验 → 入库导出 | Python · FastAPI · 视觉大模型 · 规则/勾稽/出处三层校验 | 已上线，[在线演示](https://doc-ocr-probe.app.workbuddy.host) |
| [cargo-ledger/](cargo-ledger/) | **货物台账 AI 助手**：为批发生意老板交付的进货出货台账，一句话自动追物流、盯行情 | Python · 腾讯文档 API · 快递鸟 · 两阶段写入门控 | 真实客户项目，已完整交付上线 |
| [ecom-agent/](ecom-agent/) | **跨境电商运营 Agent**：自然语言查经营数据、SQL 校验防线、高危动作人工确认 | FastAPI · Vue 3 · LangGraph · SQLGlot · Chroma | MVP 已上线，客户对接推进中 |

## 三个项目共同的设计原则

这几个项目反复验证了同一件事：**AI 落地的瓶颈通常不在模型能力，而在业务口径、数据可信和权限边界**。所以每个项目里都能看到同一套防御性设计：

1. **模型输出只当待验证输入** —— 抽取结果必须过规则校验、数学恒等式（数量×单价=金额）、出处对齐三层闸门才允许入库；结论由服务端重算，不信模型自述。
2. **没有原始证据的数字不许进统计** —— 台账「在途 38 单」口径纠错：37 条连快递单号都没有的记录被算成在途。统计字段必须能回溯到原始记录。
3. **AI 读自由、写受限** —— 高危动作（改表、改价、发消息）走两阶段确认：AI 先生成差异和一次性票据，人拍板后才执行。
4. **知道什么时候不用 Agent** —— 强流程任务用固定流水线，不给模型自主发挥空间；提示词注入实测 23 个模型，2 个被图片内嵌指令改写业务字段。
